## Visão Geral

Os **Endpoints de Webhook** permitem que sua aplicação receba notificações em tempo real sempre que eventos relevantes ocorrem na plataforma — como pagamentos aprovados, cobranças expiradas ou assinaturas canceladas.

Ao cadastrar um endpoint, a plataforma enviará um `POST` para a URL configurada com o payload do evento.

---

## Header obrigatório

Todas as rotas de webhook-endpoints exigem o header `account` com o código da conta:

```http
account: acc_abc123xyz
```

---

## Formato de resposta padrão

```json
{
  "mensagem": "Mensagem descritiva",
  "erro": false,
  "mensagenserro": [],
  "codigoretorno": 200,
  "id": "00000000-0000-0000-0000-000000000000",
  "data": { ... }
}
```

---

## Eventos disponíveis

Ao criar ou atualizar um endpoint, informe no campo `events` os eventos que deseja monitorar. A coluna **Payload** indica o formato do envelope entregue — o campo `webhook_version` do payload carrega esse mesmo valor.

<Note>
  Os payloads detalhados nesta documentação são os do formato **`v1`**, cujo envelope é `{ type, id, webhook_version, data }`. Os eventos marcados como `v2` são entregues com um envelope diferente — `{ id, type, webhook_version, created_at, data }` — e o campo `webhook_version` do próprio payload informa qual formato você recebeu. Use-o para rotear o processamento no seu endpoint.
</Note>

### Pedidos

| Evento               | Descrição                                                        | Payload    |
|----------------------|------------------------------------------------------------------|------------|
| `order.paid`         | Pedido totalmente pago                                           | `v2`       |
| `order.failed`       | Pedido falhou e nenhuma cobrança foi concluída                   | `v1` e `v2` |
| `order.refunded`     | Todas as cobranças do pedido foram estornadas                    | `v2`       |
| `order.chargeback`   | Pedido sofreu chargeback                                         | `v2`       |
| `order.challenged`   | Pedido entrou em contestação pelo antifraude                     | `v1`       |
| `order.unprocessed`  | Pedido bloqueado antes do processamento                          | `v1`       |

<Warning>
  Apenas os eventos listados acima são entregues aos endpoints da conta. Outros valores podem ser aceitos no cadastro, mas nunca resultarão em uma notificação — não construa sua integração em cima deles.
</Warning>

---

## Status do webhook

| Valor     | Descrição                                  |
|-----------|--------------------------------------------|
| `Ativo`   | Endpoint ativo — recebe notificações       |
| `Inativo` | Endpoint desativado — não recebe eventos   |

---

<Info>
  O payload enviado para o seu endpoint varia conforme o tipo de evento. Certifique-se de que sua URL retorne HTTP `2xx` para confirmar o recebimento.
</Info>

<Warning>
  Remover um webhook é uma operação irreversível. Os logs de requisições anteriores são mantidos, mas o endpoint não receberá novos eventos.
</Warning>
